# Present: First Deployment & Deploy Loop

## เวลา: 1 ชั่วโมง (6 กลุ่ม × 10 นาที)
## รูปแบบ
- อาจารย์ random 1 คนจากกลุ่มมา present — ไม่บอกล่วงหน้า
- ทุกคนในกลุ่มต้องพร้อมเสมอ
- ไม่ต้องมี slide — demo หน้าจอ

## 🎯 การ present นี้ฝึกอะไร

| สิ่งที่จะทำได้ | ใช้ในงานจริงอย่างไร |
|---|---|
| demo ระบบที่ทำงานจริงให้คนอื่นดูภายในเวลาจำกัด | demo คือรูปแบบการสื่อสารหลักในทีมพัฒนา — sprint review และการนำเสนอลูกค้าใช้รูปแบบเดียวกัน |
| ตอบคำถามเชิงเทคนิคสด ๆ โดยไม่ได้เตรียมล่วงหน้า | สัมภาษณ์งานและ design review ในที่ทำงานเป็นแบบนี้ทั้งหมด |
| อธิบายได้ว่า AI สร้างอะไรให้ และตัวเองแก้อะไรไปบ้าง | องค์กรคาดหวังให้คนที่กด merge รับผิดชอบ code นั้น ไม่ว่าใครจะเป็นคนเขียน |
| รับผิดชอบผลงานของกลุ่มร่วมกัน เพราะสุ่มว่าใครจะได้ present | สะท้อนความจริงที่ว่าทีมส่งงานร่วมกัน ไม่ใช่ต่างคนต่างส่ง |

## สิ่งที่ต้อง Present (10 นาที/กลุ่ม)

### Demo (5 นาที)
1. เปิด live URL และแสดงให้เห็นว่า app ทำงานได้
2. เปิด GitHub repo แสดง structure, README และ `AGENTS.md`
3. แสดง branch `develop` และ commit history
4. **Demo Deploy Loop สด**: แก้ข้อความ 1 บรรทัด → commit → push → เปิด URL ให้เห็นของใหม่
   (ถ้าเวลาไม่พอ ให้เปิด deployment log ของ commit ล่าสุดแทน แล้วบอกเวลาที่วัดได้)

### อธิบาย (3 นาที)
- Domain ที่เลือกคืออะไร แก้ปัญหาอะไรให้ใคร
- Stack ที่เลือกและเหตุผล
- Deploy loop ของกลุ่มใช้เวลาเท่าไร และตอนนี้ขั้น Verify มีอะไรบ้าง

### คำถาม (2 นาที)
อาจารย์อาจถาม:
- "ทำไมถึงเลือก domain นี้"
- "ถ้าเพื่อนในกลุ่มคนอื่นจะ clone repo นี้ไปรันต้องทำอะไรบ้าง"
- "AI ช่วยอะไรใน lab วันนี้ และคุณต้องแก้อะไรที่ AI สร้างมาบ้าง"
- "ถ้า deploy ครั้งนี้ทำหน้าเว็บพัง กลุ่มจะรู้ตอนไหน และรู้ได้อย่างไร"
- "ใน `AGENTS.md` มีกติกาข้อไหนที่ตั้งใจใส่ไว้กันปัญหาอะไร"

## Rubric (5 คะแนน)

| เกณฑ์ | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| **Live URL ทำงานได้** | URL ไม่ทำงาน | ทำงานแต่มี error | เปิดได้มีเนื้อหา | เปิดได้ สวยงาม | เปิดได้ + อธิบาย deploy process ได้ |
| **Deploy Loop** | ต้อง deploy มือ | auto deploy แต่ไม่รู้เวลา | auto + รู้เวลา | + demo loop สดได้ | + บอกได้ว่าจะเติม verify อะไรต่อและทำไม |
| **Repo & Context** | ไม่มี README | มี README แต่ว่าง | README + .gitignore ครบ | + `AGENTS.md` ครบ section | + อธิบายได้ว่าแต่ละกติกาใน `AGENTS.md` กันปัญหาอะไร |
| **Domain Clarity** | ไม่ชัดว่าทำอะไร | พอเข้าใจแต่คลุมเครือ | เข้าใจได้ | ชัดเจน มี user | ชัดเจน มี user + pain point + value |
| **AI Usage** | ไม่ได้ใช้ AI | ใช้ AI แต่ตอบไม่ได้ว่า output ทำอะไร | อธิบายได้บางส่วน | อธิบาย AI output ได้ | อธิบาย + บอกได้ว่าแก้อะไรจาก AI output และทำไม |

**คะแนนเต็ม: 5 คะแนน** (เฉลี่ยจาก 5 เกณฑ์)

## หมายเหตุสำหรับอาจารย์
- Random ชื่อด้วย wheel หรือ random function หน้าห้อง
- ถ้าคนที่ถูก random ตอบไม่ได้ ลด 1 คะแนนทันที แต่ให้เพื่อนในกลุ่มช่วยได้
- จุดประสงค์คือให้ทุกคนรับผิดชอบ deliverable ของกลุ่มจริง ๆ
- คำถาม "จะรู้ตอนไหนว่าพัง" คือคำถามที่จะถามซ้ำทุกสัปดาห์ ให้นักศึกษาชินกับมันตั้งแต่ครั้งแรก
